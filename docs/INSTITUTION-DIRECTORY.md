# المؤسسات التعليمية — التنظيم النهائي ولوحة الإدارة

هذه النسخة تستبدل قرار الإخفاء السابق: وافق المالك على **الحذف النهائي** لجامعة الملك سعود (`ksu`)، جامعة الملك خالد (`kku`)، وجامعة طيبة (`taibah`) وبياناتها الخاصة. لم تُنفّذ أي عملية على إنتاج Campus من بيئة التطوير.

## النشر والتنفيذ من Plesk

من جذر تطبيق Plesk الحالي، باستخدام Node.js 22 وبيئة PostgreSQL الحالية:

```sh
npm run db:migrate
npm run build
```

اسحب `main` وانشره أولًا من Git في Plesk. لا توجد اعتمادات جديدة؛ إذا كانت اعتمادات المشروع غير مثبتة، نفّذ `npm ci --include=dev` قبل الأمرين أعلاه. ثم **Restart App**. من **Node.js → Run script** أدخل اسم السكربت **`institutions:finalize`** دون معاملات؛ يعادل:

```sh
npm run institutions:finalize
```

لا يحتاج الأمر دخول Campus أو cookies أو API token أو تأكيد جديد. تشغيله صراحةً من حساب Plesk المخوّل هو التنفيذ المعتمد. يستخدم نفس منطق الحذف والفحص والمعاملة وسجل التدقيق ثم المزامنة المعتادة والتحقق النهائي. لا يعمل عند install/build/start/migration ولا ينشئ نسخة احتياطية. لا تغييرات schema جديدة لهذا الأمر؛ يجب فقط أن تكون الترحيلة الموجودة `202611010001_institution_cleanup` مطبقة لطابور حذف الملفات. لا seed ولا أسرار جديدة ولا تغيير hosting أو `server.js` أو الجدولة.

لا توجد معاملات إضافية أو وضع `--dry-run`؛ أي معاملات غير مدعومة تُرفض قبل الاتصال بقاعدة البيانات، ولا تتحول إلى حذف فعلي.

## بيئة أمر Node.js

[توثيق Plesk](https://docs.plesk.com/en-US/obsidian/administrator-guide/website-management/nodejs-support.76652/) يصف Custom Environment Variables للتطبيق وRun script لتشغيل npm؛ لا يضمن في هذا النص أن كل إصدارات Toolkit تمرر متغيرات Passenger إلى عمليات npm أو Scheduled Tasks. لم يتوفر وصول Plesk للتحقق من إصدار الإنتاج. لذلك لا نفترض تطابق البيئات:

- يقرأ الأمر `DATABASE_URL` الموروث من عملية npm، ويحمل ملف `.env` الموجود في **Application Root** بالطريقة المستعملة في سكربتات المشروع. القيمة الموروثة لها الأولوية؛ لا تُحمّل `.env.example` ولا قيم تطوير.
- يجب أن يصل `UPLOAD_DIR` الحالي نفسه عند وجود ملفات خاصة أو أعمال حذف معلقة. يرفض الأمر البدء إذا غاب أو لم يكن مجلدًا قابلًا للوصول، حتى لا يعتبر الملفات مفقودة في مسار خاطئ.
- إذا لم يمرر Plesk متغيرات التطبيق، سيظهر `DATABASE_CONFIGURATION` أو `UPLOAD_CONFIGURATION` **قبل الحذف**. عبر File Manager احفظ القيم الحالية نفسها، دون تغيير بيانات الاعتماد، في `.env` الخاص الموجود خارج `public` بجذر التطبيق، بصلاحيات قراءة لمالك التطبيق فقط (0600 على Linux). احتفظ بـ`DATABASE_URL` و`UPLOAD_DIR` المطابقين للتطبيق، بما في ذلك معاملات SSL. لا تضع القيم في معاملات npm أو لقطات الشاشة أو Git. ثم أعد الأمر نفسه.
- لا يطبع الأمر رابط قاعدة البيانات أو كلمات المرور أو الاستثناءات الخام، ولا ينشئ حسابًا إداريًا أو جلسة مزيفة. لا يتطلب `AUTH_SECRET` أو بيانات اعتماد WordPress. لا يُغيّر بيئة التطبيق أو مهمة الست ساعات، ولا يفترض أن المهمة المجدولة ترث بيئة هذا الأمر.

## النتيجة وإعادة المحاولة

مثال مخرجات **توضيحي** إذا بقي جرد المصدر عند أرقام التدقيق؛ الأعداد الفعلية تُحسب عند التنفيذ:

```text
تم حذف المؤسسات الثلاث وبياناتها الخاصة وتنظيم المؤسسات المعتمدة.
تم التحقق من 10 مؤسسات و10 روابط.
الشروحات: المصدر 198، المرتبطة 193، خارج الربط 5، المتعارضة 0.
الملفات المتبقية في طابور الحذف: 0.
اكتملت العملية بنجاح.
```

| Exit code | المعنى |
| --- | --- |
| 0 | تحقق جرد المؤسسات والروابط والشروحات، ولا ملفات معلقة |
| 1 | فشلت مرحلة الاتصال/الإعداد/الفحص/معاملة الحذف؛ لا commit جزئي للحذف في هذه المحاولة |
| 2 | تنظيم المؤسسات مكتمل، لكن المزامنة أو التحقق النهائي لم ينجح؛ أعد الأمر بعد معالجة الرمز المعروض |
| 3 | المؤسسات والشروحات متحققة، لكن حذف ملفات لم يكتمل؛ عالج صلاحيات التخزين وأعد الأمر |

المزامنة شبكة/معاملة مستقلة بعد commit تنظيم المؤسسات. فشلها لا يعيد المؤسسات المحذوفة ولا يمس آخر جرد شروحات ناجح. إعادة الأمر آمنة: علامة audit تمنع تكرار الحذف؛ يعيد فحص المؤسسات والروابط والمزامنة وحذف الملفات المعلقة. لا يتجاوز قفل المزامنة أو فحص اكتمال المصدر أو حارس الانخفاض الكبير. تشغيله الصريح يسمح بمزامنة واحدة حتى لو كانت الجدولة متوقفة، **دون تفعيل الجدولة أو تغيير إعدادها**. إذا ظهر تعارض حقيقي، أصلحه تقنيًا قبل الإعادة؛ لا تستخدم SQL لتجاوز الفحص.

تحقق بعد النجاح من `/universities` و`/courses`: عشر مؤسسات، هوية كلية ينبع الصناعية، شروح المؤسسات المضافة، والصفحات والمحتوى المشترك للمؤسسات الباقية. لا يمكن إثبات علاقات الإنتاج الخاصة أو صلاحيات Plesk/PostgreSQL 17 من الاختبارات المحلية. الأمر يفحص الحالة الفعلية عند تشغيله ويسجل النتيجة. بعد النجاح يختفي إجراء التنظيف القديم من الإدارة العادية؛ لا حاجة لفتحه أو لتأكيد داخله. رابط شاشة التسوية القديم يعيد التوجيه وطلبات الكتابة القديمة ترجع 410.

## حدود الحذف والسلامة

- فحص المالك لا يعرض حسابات أو أسرارًا: يعرض أسماء المؤسسات وأعداد العلاقات والمانع عند وجوده. البيانات الداخلية التي تستخدم لحساب بصمة الخطة لا تُرسل إلى المتصفح.
- التنفيذ يعيد التحقق من صلاحية حساب وجلسة Owner ويحمي Origin وCSRF ويطبق rate limit، ثم يقارن بصمة فحص حديث داخل معاملة Serializable.
- تُراجع العلاقات الفعلية من PostgreSQL مقابل قائمة العلاقات المعتمدة، بما فيها سلوك ON DELETE. أي علاقة جديدة أو ناقصة أو مصدر مرتبط بمحتوى مؤسسة أخرى يرفض الحذف. يشترك التنفيذ بقفل المزامنة، ويمنع الكتابة إلى جداول التطبيق خلال المعاملة القصيرة؛ فشل القفل أو المعاملة يلغيه بالكامل، دون نجاح جزئي.
- تُحذف الأخبار ووسائطها وروابط تسجيلها وسجل تحريرها، التخصصات والتدريب والأحداث والروابط، مفاتيح ومصادر وسجلات الاستيراد الخاصة، الشروح الخاصة، حسابات السفراء وجلساتها ورموز إعادة تعيينها واختياراتها المؤقتة. لا تُنقل إلى مؤسسة أخرى.
- تُحذف الإعلانات غير العامة التي تستهدف المؤسسات المحذوفة حصريًا، مع مقاييسها ومواضعها. تبقى الإعلانات العامة أو المشتركة ومقاييسها، وتُزال ارتباطاتها بالمؤسسات المحذوفة فقط.
- يُبحث عن مراجع الملفات في جميع جداول التطبيق المعروفة، بما فيها النصوص وJSON. الملف المستخدم في سجل باقٍ يُحفظ ويزال ارتباط ملكيته بالمؤسسة المحذوفة؛ لا يتغير رابطه. الملفات الخاصة تُحذف بياناتها الوصفية وتُدرج أسماؤها الآمنة في `MediaDeletionJob` داخل المعاملة. بعد commit تُحذف البايتات؛ أمر الصيانة اليومي الحالي `npm run maintenance` يعيد محاولة الملفات المتعذرة. لا يُحذف ملف قبل نجاح معاملة البيانات.
- يبقى سجل التدقيق التاريخي. علاقات محرري الأخبار الباقية وسجل التدقيق بحساب سفير محذوف تصبح null وفق القيود الحالية؛ لا يُحذف المحتوى الباقي. تبقى معرفات التاريخ والاختيارات المجمدة التي تخص مالكًا باقيًا لأغراض التدقيق/انتهاء الصلاحية؛ لا تمنح صلاحيات وتفشل الإجراءات القديمة على سجلات محذوفة.
- النجاح يسجل أعدادًا مختصرة وعلامة إتمام واحدة في audit، مع تمييز التنفيذ `plesk_cli` عن إجراء الواجهة الموجود. إعادة seed قديم بعد الإتمام لا تعيد إنشاء المؤسسات الثلاث أو مصادرها أو إعلاناتها. لا يُشغّل seed لهذا الإصدار.
- إعدادا `enabled` و`showInDirectory` ما زالا مستقلين للمؤسسات الباقية؛ التعطيل أو الإخفاء العادي ليسا بديلًا لهذه العملية النهائية.

التشخيص الخاص للمالك متاح للقراءة فقط عبر `/portal-control-x7k92/api/institution-cleanup`، كما يبقى المسار القديم GET alias؛ لا يستطيع Editor أو Ambassador الوصول إليه. لا endpoint تشغيل عام ولا حسابات طلاب.

الحذف النهائي **لا يملك زر استعادة ظهور**. إلغاء العملية قبل التأكيد لا يغير شيئًا؛ فشل المعاملة يلغيها كلها. لا تنفّذ ترحيلات عكسية أو تعيد إنشاء الجامعات الثلاث لتجاوز علامة الإتمام.
