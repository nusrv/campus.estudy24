# دليل الجامعات والمؤسسات التعليمية — التسوية الآمنة

هذه مرحلة تنفيذ قرارات المالك المبنية على [التدقيق الحي](ESTUDY24-UNIVERSITY-RECONCILIATION.md). النشر لا ينفذ التسوية؛ تبقى كل تغييرات بيانات الإنتاج تحت سيطرة المالك من المتصفح. لا تغييرات في Plesk/Node.js 22/`server.js` أو PostgreSQL أو n8n أو مفاتيحه أو سياسة النشر أو حسابات السفراء.

## الإعدادات المستقلة

| الحقل | المعنى | القيمة الافتراضية للسجلات الموجودة والجديدة |
| --- | --- | --- |
| `enabled` | تشغيل المؤسسة وصفحتها ووصول السفراء والمصادر والمفاتيح | الحقل الحالي؛ لا تغيّره الترحيلة أو التسوية للسجلات الموجودة |
| `showInDirectory` | الظهور في قوائم اكتشاف المؤسسات فقط | `true` |
| `institutionType` | `UNIVERSITY` جامعة أو `COLLEGE` كلية | `UNIVERSITY` |

إخفاء الدليل ليس تعطيلًا ولا صلاحية أمنية. المؤسسات المفعلة المخفية تظل متاحة عبر رابطها المباشر ومحتواها وإعلاناتها ومفاتيحها وجلساتها. تظل في sitemap، وتحتفظ بcanonical وبحالة الفهرسة؛ لا redirect ولا noindex بسبب إخفاء الدليل. تغيير `enabled` يبقى إجراء تشغيل مختلفًا له آثاره السابقة.

تطبّق `directoryVisibility` المشتركة على صفحة `/universities` ونتائج البحث/المناطق/الأنواع فيها، ومعاينة المؤسسات بالرئيسية، و`GET /api/universities`، وخيارات/بطاقات المؤسسات للاكتشاف في دليل الشروح. لا تطبّق على صلاحيات الإدارة، أو لوائح تعيين السفراء، أو مصادر n8n، أو المفاتيح، أو تفاصيل المؤسسة، أو الأخبار/الخدمات/الأحداث/التخصصات/الإعلانات، أو sitemap. تبقى شروح المؤسسات المخفية محتوى عامًا مشروعًا؛ إخفاء المؤسسة من قائمة اختيار عامة لا يحجب شروحها أو يمنع الوصول إلى فلترها الصريح أو تبويبها المباشر.

العنوان العام **الجامعات والمؤسسات التعليمية** مع مرشح `institution_type=UNIVERSITY|COLLEGE`، وعداد مؤسسات بأرقام غربية. يُعرض نوع المؤسسة على البطاقة، وتستخدم بوابة الكلية مسميات الكلية دون تغيير معرّفات التبويبات أو المسارات القديمة. روابط المؤسسات الموجودة لا تُعاد تسميتها. College ليس تصنيف تدريب، ويظل `AcademicProgram` مستقلًا عن `CourseExplanation`.

## إدارة الظهور اليومية

المالك فقط: **إدارة الجامعات والمؤسسات → تعديل السجل → إظهار في دليل المؤسسات التعليمية**.

تشرح الواجهة: **يؤثر هذا الخيار على ظهور المؤسسة في قوائم التصفح فقط، دون تعطيل صفحتها أو محتواها أو تكاملاتها.**

الحقل **المؤسسة مفعّلة تشغيليًا** مستقل، والتحذير يوضح أثر التعطيل. إجراءات التحديد المشتركة تدعم **إظهار المحدد في الدليل فقط / إخفاء المحدد من الدليل فقط**، منفصلين عن تفعيل/تعطيل التشغيل. تُستخدم آلية التأكيد واللقطات والمعاملات والتدقيق الحالية؛ لا تمنح المحرر أو السفير امتيازًا جديدًا. طلبات التحرير القديمة التي لا ترسل حقلي الظهور/النوع لا تصفرهما.

## A — نشر الكود والترحيلة فقط

الترحيلة الإضافية الوحيدة: **`202610290001_institution_directory`**. تضيف enum وحقلين وفهرسًا. لا `UPDATE` بيانات أعمال ولا إنشاء مؤسسات/روابط ولا حذف أو reset؛ المؤسسات الموجودة تحتفظ بـIDs وslugs وenabled، وتبدأ ظاهرة في الدليل كما كانت.

بعد النسخة الاحتياطية التشغيلية المعتادة، في Plesk: **Git Pull → Deploy** إلى Application Root الحالي، ثم من بيئة Node.js 22/npm الحالية وباستخدام `DATABASE_URL` الموجود:

```sh
npm ci --include=dev
npm run db:migrate
npm run build
```

تحقق من نجاح كل أمر ثم **Node.js → Restart App**. `build` يولّد Prisma Client كالمعتاد. لا متغيرات بيئة جديدة، ولا seed أو نسخ assets أو تعديل Document Root/Startup File أو cron أو أسرار. لا يشغّل build/startup/migration التسوية، ولا يجب تشغيل script لتحديث الإنتاج مباشرة. الجدولة السابقة للمزامنة كل 6 ساعات تبقى كما هي.

## B — فحص إنتاج للقراءة فقط بواسطة المالك

افتح **فحص وتسوية دليل المؤسسات** في `/portal-control-x7k92/institution-reconciliation`.

- تعرض الصفحة **كل المؤسسات بما فيها المعطلة**: ID، الاسم، slug، النوع، الحالة التشغيلية وقرار الظهور.
- توسّع **العلاقات بكل الحالات** لرؤية أعداد الأخبار والأحداث والتخصصات والتدريب والروابط والإعلانات والوسائط والحسابات والمصادر والمفاتيح والشروح والربط. الأعداد تشمل المسودات والمحذوفات حيث بقيت صفوفها؛ ليست أعداد API العام.
- تُعرض أعداد الحسابات حسب الدور/الحالة وعدد المفاتيح غير الملغاة فقط، **دون أسماء/بريد الحسابات أو hashes أو sessions أو أسرار**. تعرض المصادر ID/key/الحالة والجامعة وأعداد علاقاتها بالمقالات وسجلات الاستيراد و`ContentSync` والتخصصات، دون URLs قد تحتوي أسرارًا. `_count` لا يعني تحليل جميع الإشارات التاريخية داخل JSON؛ سجل التدقيق والتحرير يبقى محفوظًا وغير محذوف، ويمكن للمالك مراجعته في واجهاته الحالية عند الحاجة.
- تعرض الصفحة صفوف ربط التصنيفات الحالية. يجب أن تشير الروابط السبعة المعتمدة إلى سجلاتها الحالية وتكون مفعلة؛ أي فقد/اختلاف/تعطيل يُعرض كمانع، ولا تصلحه التسوية تلقائيًا.
- تبرز السجلات المحتملة للباحة وتبوك وينبع بالأسماء/المعرّفات الدالة، بما فيها المعطلة. هذه **إشارات لتدقيق المالك، وليست ربطًا تلقائيًا بالتشابه**. تكرار مرشحين أو تعارض هدف ربط أو slug محجوز يوقف التنفيذ. تُعرض القائمة الكاملة أيضًا للتحقق من السجلات ذات الأسماء المخصصة التي لا يمكن التعرف عليها آليًا.
- يجب وجود تصنيفات المصدر 287 و159 و310 محليًا بأسمائها المتوافقة. إن لم تُسترجع من قبل، راجع إعداد المزامنة وقم بمزامنة عادية صريحة من حساب المالك عند اعتماد ذلك، ثم أعد الفحص؛ لا ينشئ الفحص تصنيفات أو مؤسسات.

`GET /portal-control-x7k92/api/institution-reconciliation` فحص مصادق ومخوّل للمالك فقط؛ القراءة داخل معاملة Repeatable Read ولا تكتب بيانات أو audit. صفحة الإدارة تمنع الفهرسة كالمعتاد. لا endpoint تشغيل عام ولا حسابات طلاب.

## C — قرار المالك وتنفيذ المعاملة

لكل مؤسسة معتمدة:

| المصدر | الهوية والنوع | موافقة المالك المطلوبة |
| --- | --- | --- |
| 287 | جامعة الباحة — `UNIVERSITY` | ID موثّق لإعادة الاستخدام، أو slug جديد يكتبه المالك بعد التأكد من عدم وجود سجل |
| 159 | جامعة تبوك — `UNIVERSITY` | القرار نفسه |
| 310 | كلية ينبع الصناعية — `COLLEGE` | هوية كلية مستقلة؛ لا تسمية جامعة ولا دمج مع غيرها |

1. عند وجود سجل حقيقي مطابق، اختر **إعادة الاستخدام** بالـID بعد مراجعة الهوية، لا إنشاء نسخة. الأسماء المخصصة لا تُستبدل ولا تتغير IDs أو slugs. السجل المعطل **يبقى معطلًا**؛ إذا أراد المالك تشغيله، فهذا قرار صريح منفصل من تحرير المؤسسة ثم فحص جديد، وليس ضمن التسوية.
2. عند غياب السجل، اختر **إنشاء** واكتب slug جديدًا معتمدًا. لا تقترح الأداة slug نيابة عنك. إنشاء المؤسسة يتطلب تأكيد الهوية وعدم التكرار؛ الاسم والنوع هما المعتمدان أعلاه. لا يُخترع شعار أو موقع أو معلومات اتصال؛ الحقول الاختيارية تبقى null/فارغة. يمكن للمالك إضافتها لاحقًا بعد التحقق.
3. أكد مربع هوية/نوع/ظهور/ربط كل مؤسسة، بما فيه موافقة تفعيل الربط الجديد إن كان الربط نفسه معطّلًا. وجود ربط لتصنيف جديد بجامعة أخرى يرفض العملية بدل إعادة تعيينه. استخدام السجلات الأصلية السبعة أو الثلاثة المراد إخفاؤها كبديل لهوية جديدة مرفوض.
4. اضغط **مراجعة التسوية قبل التنفيذ**، راجع أسماء/IDs/slugs الثلاثة وما سيُنشأ وما سيُستخدم، ثم اكتب **تأكيد تسوية دليل المؤسسات** ونفّذ.

ينفذ POST المخول والمحمي بـCSRF وحد حجم الطلب وrate limit معاملة Serializable واحدة، ويشارك قفل catalog mapping الحالي. يُقارن fingerprint بالفحص الحي مجددًا ويُعاد التحقق من حساب وجلسة المالك. البيانات المتغيرة أو الموافقة القديمة أو التعارض أو خطأ المعاملة تفشل دون نجاح جزئي. أعد الفحص بعد 409؛ لا تفترض أن نتيجة قديمة ما زالت صالحة. قد يُرفض سباق متزامن بتعارض معاملات؛ إعادة الفحص آمنة.

النتيجة المعتمدة:

- إنشاء/إعادة استخدام الهويات الثلاث بالنوع الصحيح، وإظهارها في الدليل؛ المحافظة على enabled للسجلات الموجودة.
- إنشاء/التحقق من روابط 287/159/310 باستخدام IDs الفعلية فقط؛ لا تعديل أو إعادة إنشاء للروابط السبعة الأصلية.
- الروابط الإضافية السابقة للمؤسسة الموثقة تبقى كما هي، بما فيها الروابط المعطلة؛ لا تُحذف لتسهيل إعادة الاستخدام. ما زال ربط هويتين مختلفتين من الثلاث المعتمدة بالسجل نفسه مرفوضًا.
- تعيين `showInDirectory=false` للـIDs الحالية التي slugs لها ksu/kku/taibah، **دون أي تعديل enabled أو حسابات أو مفاتيح أو مصادر أو روابط محتوى**.
- إعادة حساب إسقاط ربط الشروح المحلية بالدالة الحالية `remapCourses`، دون اتصال WordPress أو حذف أو تغيير `sourcePublished`؛ الشروح المصنفة حديثًا قد تظهر فورًا إذا كانت محفوظة بالفعل. سجلات `unknown` الأخرى تبقى خارج القوائم العامة.
- تسجيل القرار والمعرّفات وحالات قبل/بعد في audit. إعادة التسوية بعد فحص جديد واختيار إعادة استخدام السجلات الثلاثة آمنة؛ لا مؤسسات أو روابط مكررة. إعادة إرسال نفس fingerprint بعد تغيّر البيانات تُرفض بدل إعادة تنفيذ غير مُراجع.

لا يُسمح بالتخمين عند تعارض إنتاج لا يمكن حسمه. أوقف الخطوة وراجع السجل/الهوية مع المالك؛ لا تحذف السجل لتجاوز المنع، ولا تُعدّل الربط الأصلي السباعي لإرضاء العملية.

## D — المزامنة والتحقق العام

بعد المراجعة اضغط **مزامنة الآن** العادية في **دليل شروحات eStudy24 والربط**. لا مسار استيراد جديد ولا تغيير workflow أو payload. تبقى حمايات الجرد الكامل والـlease والمعاملة والحذف الكبير والتحرير/المجالات مستقلة كما هي.

أعداد التدقيق الأصلية للمقارنة فقط: 184 شرحًا لتسع جامعات +9 لكلية ينبع =193 عبر عشر مؤسسات؛ 5 خارج الروابط العشرة. ليست ثوابت في الكود أو ضمانًا للأعداد الحالية. يجب فحص حالة التشغيل للمؤسسة المعاد استخدامها إذا لم تظهر، وعدم تفسير صف عام صفري كخلو بياناتها.

تحقق بعد النشر، بيد المشغل:

- تظهر الباحة وتبوك وكلية ينبع بعد اعتمادها وتشغيلها، مع البحث ومرشح الجامعات/الكليات، والأسماء والأنواع الصحيحة.
- لا تظهر ksu/kku/taibah في الدليل أو معاينة الرئيسية أو خيارات اكتشاف المؤسسات في الشروح؛ روابطها المباشرة وصفحات المحتوى وcanonical وsitemap تعمل.
- جلسة سفير موجود ومفتاح n8n الحالي يظلان صالحين؛ لا تدوير مفاتيح أو تسجيل خروج مطلوب بسبب تغيير الظهور. تحقق من أحدث ingestion فعلي بالطريقة التشغيلية المعتمدة دون مشاركة أسرار.
- الروابط السبعة وIDs/slugs الأصلية كما كانت؛ لا حذف سجلات أو تغيير ارتباط أخبار/تخصصات أو إعلانات.
- افحص نجاح المزامنة وأعدادها والتصنيفات غير المرتبطة وأول تشغيل مجدول؛ لا تستخدم مساواة العدد 193 وحدها معيارًا للصحة إذا تغير المصدر.
- تحقق من CSS/JavaScript والخطوط عبر `server.js` كما في [PLESK.md](PLESK.md). لا اختبارات إنتاج أو نشر آلي نُفّذت من بيئة التطوير.

## التراجع دون استعادة قاعدة البيانات

في صفحة الفحص حدّث البيانات ثم اختر **استعادة ظهور الجامعات الثلاث فقط**، وراجع واكتب **إظهار الجامعات الثلاث في الدليل**. تعيد المعاملة `showInDirectory=true` للـIDs الحالية لـksu/kku/taibah فقط، مع حماية الجلسة/CSRF/fingerprint والتدقيق. لا تحتاج build أو restart بعد تغيير بيانات الظهور.

هذا تراجع لقرار الإخفاء، لا حذف للهويات الثلاث الجديدة ولا إزالة لروابطها أو محتواها. يمكن للمالك تعديل ظهور أي مؤسسة منفردة أو جماعيًا أيضًا. تبقى إعدادات التشغيل الحالية كما هي؛ إذا غيّرها المالك لاحقًا لا يعكسها زر التراجع تلقائيًا. لا تُحذف الترحيلة ولا تستخدم reset/db push/تحديث SQL واسع للتراجع.

## سلامة seed

`seed-campus.ts` يستخدم upsert بالـslug مع `update: {}` للجامعة، ولا يملأ حتى URL أفرغه المالك عمدًا. لا يبدّل الاسم أو النوع أو الظهور أو enabled أو يعيد تفعيل مؤسسة قديمة. لا يزيل روابط التصنيفات الجديدة، ولا يضيف المؤسسات الثلاث الجديدة تلقائيًا. تظل الإعلانات/المصادر الأولية ذات الهويات الثابتة وسلوك الحفظ السابق، ولا تُنشأ حسابات.

seed الأساسي يحفظ الموجود، وتهيئة الربط السباعي تحفظ تعديلات/تعطيل الربط ولا تنشئ جامعات. أمر الشعارات الاختياري الصريح يملأ الشعارات الناقصة فقط، ولا يغير إعدادات التشغيل/الظهور؛ لا تشغله ضمن هذه التسوية. **لا seed مطلوب لهذا الإصدار.**

## تشخيص IAU رقم 33899

قراءة عامة جديدة عند **2026-10-29 12:14:59 UTC**: المصدر يعيد HTTP 200 و`status=publish` وتصنيف `[378]` و`modified_gmt=2026-10-28T08:05:23`، بينما قائمة Campus العامة ما زالت 9 ولا تضم رابط السجل. لا دليل على أن ربط IAU نفسه خطأ.

الاختبارات المحلية تتحقق أن السجل المنشور الموافق للمخطط يُدرج ويُربط بـIAU ويظهر بعد مزامنة عادية متكررة دون تكرار؛ يُوثق اختبار المصدر الحي ونتائجه في تقرير التحقق. **سبب الفشل الخاص بإنتاج Plesk لا يمكن الجزم به بلا فحص المالك للسجل والمحاولات الفعلية.** لا يُدّعى إصلاح defect في collector لم يُستنسخ، ولا تُشغّل مزامنة إنتاج لأجل التشخيص.
