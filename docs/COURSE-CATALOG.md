## النطاق والمعمارية

Campus دليل عام مجاني لاكتشاف شروحات eStudy24، وليس نظام تعلم أو شراء آخر. المسار الجديد `/courses` وتبويب **شروحات المواد الدراسية** في بوابة الجامعة يعرضان بيانات محلية وروابط **عرض الشرح** إلى المنصة الأصلية. لا توجد حسابات طلاب أو تسجيل أو دفع أو طلبات مواد أو دروس مضمّنة. بقيت التبويبات التسعة السابقة ومعرّفاتها وترتيبها دون تغيير.

المصدر ثابت على النطاق الموثوق:

- `GET https://estudy24.com/wp-json/wp/v2/courses`
- `GET https://estudy24.com/wp-json/wp/v2/course-category`

مرجع الترقيم الرسمي: [WordPress REST API pagination](https://developer.wordpress.org/rest-api/using-the-rest-api/pagination/)، بما فيه حد `per_page=100` وترويستا إجمالي السجلات والصفحات.

تستخدم المزامنة واجهة WordPress العامة دون بيانات اعتماد، ولا تستدعي Tutor LMS المحمي أو WooCommerce أو المستخدمين أو الطلبات أو الاشتراكات أو الدروس. تُطلب فقط حقول تعريف الشرح والعنوان والوصف العام والرابط والتصنيفات وتاريخ التعديل والصورة المضمّنة. لا يرسل المتصفح طلبات لواجهة WordPress؛ يحمل الصور العامة المختارة فقط.

نماذج مستقلة تمامًا عن `AcademicProgram` ومصادره وقواعد الحذف: `CourseExplanation`، `CourseSourceCategory`، `CourseUniversityMapping`، `CourseCatalogSettings`، `CourseSyncRun`. الهوية هي رقم WordPress الثابت، وليست عنوان المادة أو معرّف تخصص أكاديمي. المزامنة هي الجهة التي تدير سجلات الشروحات؛ لا توجد واجهة تحرير يدوية أو حذف جماعي لها تمنع تحديث المصدر لاحقًا.

لا يملك المحرر أو السفير إدارة المزامنة أو التصنيفات العالمية أو سياستها؛ بقيت صلاحياتهما الحالية على محتوى Campus دون توسيع. أسماء التصنيفات ومعرّفات المصدر وسجل المزامنة لا تُنشر عبر API العام.

## المزامنة والسلامة

`npm run courses:sync` عملية قصيرة مستقلة تناسب **Scheduled Tasks** في Plesk، كل 6 ساعات. لا توجد مؤقتات داخل `server.js`، ولا تتوقف المواعيد على وجود زائر، ولا توجد نقطة تشغيل عامة أو مفتاح cron في URL. يبدأ الخيار متوقفًا حتى يفعله المالك؛ الأمر المجدول يتخطى الحالة المتوقفة أو محاولة أخرى قيد التنفيذ دون خطأ تشغيلي.

1. حجز مؤقت ذري في PostgreSQL لمدة 15 دقيقة يمنع تداخل التشغيل اليدوي والمجدول وعمال Plesk. تُسجل المحاولة قبل الاتصال بالمصدر. الحجز المتروك إثر توقف العملية ينتهي تلقائيًا؛ تُوسم المحاولات القديمة المقطوعة بالفشل عند التشغيل التالي.
2. جلب التصنيفات والشروحات المنشورة فقط، بترتيب ID وبحد 100 سجل لكل صفحة، وفق `X-WP-Total` و`X-WP-TotalPages`. الطلبات متسلسلة، بمهلة 20 ثانية للطلب، و3 محاولات إضافية بتراجع أُسّي لأخطاء الشبكة و429 و5xx المؤقتة. تُراعى `Retry-After` حتى 30 ثانية. المهلة العامة 180 ثانية؛ 100 صفحة/10000 سجل كحد أقصى لكل مورد، و16 MiB لكل استجابة. التحويل إلى نطاق/مسار آخر مرفوض، ولا تتبع تحويلات HTTP.
3. التحقق من عدد السجلات وتغيّر حدود الصفحات والتكرار ومعرّفات التصنيفات وحقول كل شرح. تُعاد مقارنة الصفحة الأولى عند تعدد الصفحات. لا تقدم WordPress معاملة snapshot موزعة؛ هذه الفحوص تقلل خطر تغيّر المصدر أثناء الجلب، وأي عدم اتساق مكتشف يوقف التشغيل كله.
4. تحليل HTML على الخادم أثناء المزامنة باستخدام `parse5`، ثم حفظ نص عادي يُعرض عبر React دون `dangerouslySetInnerHTML`. يُحفظ العنوان الأصلي كاملًا بعد فك HTML/entities وتوحيد المسافات فقط، بما فيه الرموز والأرقام والأقواس وأسماء الأقسام؛ لا يُقص عند 500 حرف ولا تُعاد صياغته. لا يوجد حقل مستقل لرمز المقرر. يُختار الملخص من مقدمة المحتوى المنظم أولًا، ثم المقتطف المناسب عند الحاجة، مع استبعاد الروابط والدعم والأسعار والاشتراكات والاسترداد والعبارات الترويجية. عند عدم وجود مقدمة مناسبة يُحفظ النص: **شرح المادة متوفر على منصة eStudy24.** لا تُنفّذ عناصر المصدر أو سكربتاته ولا تُحفظ الاستجابة الخام.
5. الروابط والصور HTTPS فقط على `estudy24.com` أو `www.estudy24.com`، دون بيانات اعتماد أو منفذ أو query أو fragment. الصور من `/wp-content/uploads/` بصيغ raster معروفة؛ تُفضّل الأحجام المتوسطة المضمّنة المطابقة لمعرّف الصورة. لا تنزيل أو إعادة نشر أو تحويل صور عبر خادم Campus؛ يظهر بديل بصري عند غيابها أو فشلها.
6. تطبيق الجرد المتحقق كله في معاملة واحدة، باستخدام upserts على WordPress ID، وإعادة قراءة الربط والإعدادات داخل المعاملة. لا تعديل للدليل السابق عند فشل صفحة أو سجل أو معاملة. تعاد مراجعة جلسة المالك قبل إقرار تشغيل يدوي، حتى لا تنفذ جلسة أُلغيت أثناء الجلب.
7. الغائب عن جرد ناجح يُوسم `sourcePublished=false` دون حذف بياناته. عودته منشورًا تُفعّله طبيعيًا. لا تُستخدم tombstones التخصصات/الأخبار. لا يغيب شرح من الدليل بسبب عدم وروده في صفحة فاشلة.

إذا كان الدليل السابق غير فارغ، يُرفض الجرد الفارغ دائمًا. يُحجز أيضًا أي انخفاض يتجاوز الأكبر من **5 شروحات أو 20% من السجلات المنشورة سابقًا**، ويحفظ سجل `REMOVAL_GUARD` مع العدد وبصمة الجرد. بعد التحقق يدويًا من المصدر يستطيع المالك كتابة **تأكيد تسوية N شرح** في الشاشة الخاصة. يُعاد الجلب، ولا تقبل الموافقة إلا لنفس بصمة الجرد ونفس العدد خلال ساعة. المجدول لا يملك تجاوز الحماية. الجرد الفارغ لا يقبل هذا التجاوز. تُسجّل الموافقة في AuditLog؛ لا يوجد حذف مادي جماعي.

تظهر آخر 10 محاولات، أعداد الجلب والربط والتعارض والغائب، رمز الخطأ، وآخر نجاح في شاشة الإدارة. تعرض الشاشة معاينة تشخيصية لأول 30 شرحًا يحتاج الربط مع العدد الكلي. هذه شاشة تقرير دون عمليات سجلية وليست قائمة تحرير محتوى إضافية. أخطاء الشبكة تبقي آخر نجاح كما هو؛ أخطاء التفويض/التحقق الدائمة لا يعاد إرسالها بلا تغيير. السجلات لا تحتوي أجسام المصدر أو كلمات مرور أو URL قاعدة البيانات أو مفاتيح API.

## العرض العام والدعم

`GET /api/courses` يدعم `university` و`search` و`page` و`page_size` (1–100؛ الافتراضي 12). لا يقبل فلاتر إدارية. لا يعرض إلا شروحات منشورة ذات ربط وحيد بجامعة مفعلة. الاستجابة: عنوان عرض، ملخص نصي، صورة، رابط eStudy24، اسم الجامعة وslug، بيانات الترقيم وقائمة الجامعات المشاركة فقط. لا يعرض ID المصدر أو معلومات التشغيل أو بصمات الجرد.

البحث محلي ومطبع للعربية والإنجليزية وحالة الأحرف، مع المحافظة على العنوان الأصلي في البيانات الخاصة. صفحة `/courses` ضمن sitemap، ولا توجد صفحات شرح داخلية مكررة. روابط العرض تفتح المنصة الأصلية في تبويب جديد مع `noopener noreferrer`.

ترويج الرئيسية يحافظ على المحتوى التحريري الحالي ويوجه للدليل. الدعم العائم الصغير يستخدم **رابط دعم تيليجرام الموجود في إعدادات المنصة**؛ لا توجد قيمة مفترضة ولا رابط مخترع. يظهر في دليل الشروحات وتبويب الشروحات فقط عند تكوين رابط آمن. يدير المالك هذا الرابط من الإعدادات الحالية. رابط دعم المنصة مستقل عن مجتمعات الجامعات. لا يجمع Campus بيانات تواصل الطلاب أو طلباتهم.

## تصحيح دقة البيانات والبطاقات المدمجة — بعد الإصدار aad3103

### الأسباب المؤكدة

- كان `courseDisplayTitle` يحذف أنماط رموز المقررات ثم الأقواس والشرطات المتبقية قبل الحفظ؛ كان API يعرض `title` المعدّل وليس `sourceTitle`. كما قصّ `parseCourse` العنوان عند 500 حرف. أطول عنوان في الجرد الحي المفحوص 82 حرفًا، لذا فقدان الرموز هو العيب الفعلي المثبت في الأمثلة الحالية، وقيد 500 حرف كان عيبًا إضافيًا للعناوين المستقبلية الطويلة.
- يدمج WordPress محتوى الفقرات والروابط في `excerpt.rendered`. أثبت السجل 9182 وجود `الدعم الفني<a href="https://t.me/eStudy_24">…</a>` في المحتوى، بينما يصبح `الفنيhttps://t.me/…` في المقتطف. فضّل الكود القديم هذا المقتطف، وأسقط بنية HTML، ثم قسم النص على كل نقطة؛ انقسم `youtu.be` و`t.me` إلى أجزاء وبقيت بقايا روابط بعد حذف المقاطع التجارية. كما استبعدت قاعدة رموز المقررات مقدمات أكاديمية سليمة.
- كانت البطاقة عمودية بثلاثة أعمدة، وصورة `aspect-[4/3]` تمتد بعرضها، ومسافات `gap-4 p-5` قبل النص وزر كامل العرض؛ لذلك هيمنت الصورة والفراغ على بطاقة اكتشاف المادة.

### السياسة المصححة

`src/server/course-text.ts` يستخدم شجرة HTML5 خاملة بدل regex لإزالة الوسوم. يحافظ على الفواصل بين الفقرات و`br`، وعلى النص داخل عناصر التأكيد دون شطر الرموز المضمنة. يفك entities المسماة والرقمية وUnicode، ويستبعد السكربتات والأنماط والنماذج والعناصر المضمّنة والمخفية من الملخص. لا يعيد تفسير النص المفكوك كـHTML. مكتبة التحليل محصورة في المزامنة على الخادم؛ المتصفح وAPI العام يقرآن النص المحلي المحفوظ.

تُفضّل مقدمة `content.rendered` المنظّمة على المقتطف المسطح. تُستبعد روابط الفيديو/التواصل من عقد anchors، وتُكتشف الروابط العارية والمشوهة قبل تقسيم الجمل. لا تُفصل الروابط عند النقاط مطلقًا. تبقى تسميات الروابط الأكاديمية المناسبة نصًا دون href. تُرفض فقرات الدعم والاتصال والاشتراك والاسترداد والتسعير والعبارات العامة غير المناسبة، ويتوقف الاختيار عند الدخول إلى القسم التجاري. تُحفظ مقدمة موجزة تصل إلى جملتين وبحد 360 حرفًا تقريبًا عند نهاية كلمة؛ لا يُنشأ وصف من اسم المادة أو من معلومات مستنتجة. عدم كفاية المصدر ينتج الرسالة الاحتياطية المحددة.

لا تغيّر قواعد التنقية مصطلحات أكاديمية مثل الرسوم البيانية، الدفع والزخم، استرجاع المعلومات، مجموعات الأعداد أو متجهات الدعم إلى معلومات تجارية. تبقى الأرقام وعلامات الترقيم والرموز في العنوان كما قدمها المصدر؛ تبقى إحصاءات الواجهة وترقيم الصفحات بالأرقام الغربية. البحث المحلي يدعم العناوين الكاملة والرموز المضمنة، بحد 2000 حرف موحد بين نموذج البحث والخادم، دون حقل code مستقل.

### البطاقات المدمجة

تُستخدم `CourseCard` نفسها في `/courses` وتبويب الجامعة. الصورة المصغرة 56×42 على البطاقات الضيقة و96×72 عند اتساع البطاقة، مع `object-fit: contain` دون قص الصور أو استبدالها. زر **عرض الشرح** يبقى رابطًا مباشرًا آمنًا؛ في البطاقة الواسعة يقع في عمود ثابت مقابل الصورة، وفي الضيقة في صف سفلي قابل للنقر بسهولة. يبقى اسم الجامعة ظاهرًا.

العنوان يلتف كاملًا دون line-clamp أو ellipsis؛ قد تكبر بطاقة عنوان استثنائي طويل لحفظ المعلومات، ولا تتمدد البطاقات المجاورة لارتفاعه. الملخص محدود بصريًا بسطرين مع بقاء النص متاحًا لأدوات الوصول. الشبكة تعرض بطاقتين عندما يتسع المحتوى الفعلي لذلك، وتراعي الشريط الإعلاني في صفحات الجامعات باستخدام container queries؛ لا تُفرض أعمدة ضيقة بسبب عرض الشاشة وحده. لم تتغير الهوية أو التنقل أو آلية Plesk.

### تحديث الإصدار المصحح على Plesk

هذا التصحيح **لا يحتاج ترحيل Prisma أو seed أو متغيرات بيئة جديدة**. يعتمد على جداول الإصدار المنشور أصلًا، ويضيف اعتماد تشغيل واحدًا `parse5` مع الاعتماد الانتقالي `entities` عبر lockfile. بعد **Pull Updates → Deploy** في الجذر الحالي وباستخدام Node.js 22:

```sh
npm ci --include=dev
npm run build
```

ثم **Restart App**. افتح شاشة دليل شروحات eStudy24 بحساب المالك واضغط **مزامنة الآن** مرة واحدة؛ أو انتظر المزامنة المجدولة التالية الناجحة. تُعاد حسابات العناوين والأوصاف لكل سجل في الجرد، حتى لو لم يتغير `modified_gmt`، لأن upsert الحالي يحدث الحقول دائمًا بواسطة WordPress ID الثابت. لا تتغير هوية السجل أو إعدادات الربط أو حالة المصدر بسبب هذا التصحيح، ولا تُستخدم نصوص SQL أو إعادة ضبط أو حذف لإنجاز الإصلاح. تبقى ضمانات الجرد الكامل، المعاملة، التأجيل عند الفشل وحارس الانخفاض الكبير كما هي.

## النشر الأول لدليل الشروحات على Plesk — للمراجعة فقط

ترحيل إضافي واحد: `202610270001_course_catalog`. ينشئ جداول الدليل المنفصلة، ولا يحذف أو يعيد تصنيف محتوى قائمًا ولا يغيّر الحسابات أو مفاتيح n8n. لا توجد متغيرات بيئة تطبيق جديدة أو اعتماديات جديدة أو تغيير في `server.js` أو إعدادات Next.js.

بعد النسخ الاحتياطي المعتاد، نفّذ **Pull Updates → Deploy** في جذر التطبيق الحالي، ثم باستخدام Node.js 22.14 أو أحدث:

```sh
npm ci --include=dev
npm run db:generate
npm run db:migrate
npm run courses:seed-mappings
npm run build
```

إذا أردت إدارة الروابط السبعة يدويًا بدل الأمر، يمكن تجاوز `courses:seed-mappings`. الأمر متكرر وآمن ولا يستبدل قرارات المالك. بعد نجاح البناء اضغط **Restart App**. أبقِ جذر التطبيق الحالي، Document Root داخل `public`، ملف التشغيل `server.js`، إعدادات PostgreSQL والبيئة ورفع الملفات والتكاملات. لا reset أو db push أو نسخ ملفات build.

1. سجّل الدخول كمالك وافتح **دليل شروحات eStudy24 والربط**، وراجع الجامعات المرتبطة.
2. اضغط **تفعيل المزامنة** ثم **مزامنة الآن**، وانتظر نتيجة المحاولة. راجع غير المرتبط والمتعارض؛ لا تعالج التصنيفات التعليمية العامة بربط عشوائي.
3. تأكد من عرض الدليل والجامعات المطابقة على الموقع العام قبل جدولة التكرار.
4. في Plesk افتح **Scheduled Tasks** لنفس مستخدم الاشتراك. اختر **Run a command**، واجعل الجدول cron هو `0 */6 * * *` (توقيت خادم Plesk)، مع مسار Node.js 22 المثبت فعلًا ومسار التطبيق المطلق من شاشة Node.js.
5. المهام المجدولة قد لا ترث متغيرات بيئة تطبيق Node.js في Plesk. وفّر `DATABASE_URL` الحالي في بيئة المهمة بصورة محمية، أو في ملف بيئة خاص خارج Document Root، قابل للقراءة لمستخدم الاشتراك فقط. لا تضع قيمة الاتصال في command أو URL أو Git أو سجل المهمة، ولا تستبدل إعدادات التطبيق الحالية.

صيغة الأمر عند استخدام ملف بيئة خاص (استبدل المسارات فقط بالقيم الفعلية الظاهرة في اشتراكك):

```sh
cd /ABSOLUTE/APPLICATION_ROOT && /opt/plesk/node/22/bin/node --env-file=/ABSOLUTE/PRIVATE/campus-catalog.env --experimental-strip-types scripts/sync-courses.ts
```

يحتوي الملف الخاص على `DATABASE_URL` الموجود لديك فقط؛ لا تحتاج بيانات اعتماد WordPress أو `AUTH_SECRET` لتشغيل المجدول. أعط الملف صلاحية `600` وملكية مستخدم الاشتراك، ولا تنسخه إلى `public`. مسار الملف ليس سرًا، ومحتواه لا يوضع في arguments. إذا ورثت المهمة `DATABASE_URL` بالفعل، احذف `--env-file` فقط. استخدم المسار الفعلي لـ Node.js في اشتراكك إذا اختلف عن المثال. لا يُفترض جذر مطلق غير معروف أو حاوية/خدمة إضافية.

فعّل إشعارات فشل المهمة، وافحص سجل المزامنة بعد أول موعد. للإيقاف المؤقت استخدم خيار **إيقاف المزامنة**؛ يبقى آخر دليل صالح متاحًا. لا يوجد إعداد schedule داخل التطبيق يحتاج restart؛ جدولة Plesk خطوة تشغيل صريحة لم تُنفّذ من بيئة التطوير.
