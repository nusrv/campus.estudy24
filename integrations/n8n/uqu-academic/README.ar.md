# جمع التخصصات والبرامج الأكاديمية لجامعة أم القرى

هذا سير عمل مستقل للدرجات والتخصصات الأكاديمية فقط. لا يغيّر سير الأخبار أو الفعاليات أو التقويم أو الخدمات. ملف الاستيراد: **`uqu-academic-programs.workflow.json`**. الوضع الافتراضي **`dry_run`**، والتفعيل `active=false`، ولا يوجد مشغّل زمني أو مفتاح سري في الملف.

## ما تحققنا منه في المصدر

تم فحص [الدليل الرسمي](https://uqu.edu.sa/App/Degrees) في 22 أكتوبر 2026. تصل البيانات في HTML من الخادم؛ لا يحتاج الجمع إلى متصفح مسجّل الدخول أو استدعاء واجهة JSON مفترضة. الصفحة تستخدم مكوّن Livewire باسم `single-apps.degrees`. ظهرت إعدادات البحث والمرشحات العامة `searchQuery`, `city`, `faculty`, `dept`, `degree`, `price`, `perPage` وترقيم `page` في حالة المكوّن العامة. جرى اختبار `page=2` و`perPage=100` عبر GET فعليًا؛ لا نفترض اختبار جميع تراكيب المرشحات. لا نرسل طلبات Livewire أو نماذج تسجيل الدخول ولا نحفظ جلساتها.

الجمع الكامل استخدم أربع طلبات متسلسلة إلى `https://uqu.edu.sa/App/Degrees?perPage=100&page=N` بفاصل لا يقل عن ثانيتين. أعاد المصدر 337 صفًا: 100، 100، 100، 37. بعد إزالة أربعة صفوف متطابقة تحمل المعرف الرسمي نفسه بقي **333 برنامجًا مختلف المعرف**. هذه أعداد وقت الاختبار، وليست أعدادًا ثابتة داخل سير العمل. يتم اكتشاف العدد والصفحة النهائية من استجابة المصدر في كل تشغيل. ملف `robots.txt` العام وقت الفحص لم يمنع هذا المسار؛ يجب احترام أي تغيّر لاحق في سياسة الموقع.

لكل صف رابط رسمي مثل `/App/Degrees/1894`. يستخدم الجامع الجزء الرقمي الأصلي نفسه بوصفه `source_id`، لا الاسم ولا موقع الصف. يبقى `source_key=uqu-degrees` ثابتًا. لا تغيّر هذه القاعدة بعد أول استيراد؛ تغييرها ينتج هويات جديدة. الأسماء المتشابهة بدرجات أو نسخ مختلفة ذات معرفات رسمية مختلفة لا تُدمج. تكرار المعرف ببيانات متعارضة يوقف الإرسال بدل اختيار نسخة عشوائيًا.

تُقرأ أسماء البرنامج والدرجة والكلية/القسم والساعات من أعمدتها. يفصل الكلية والقسم فقط عندما يعرض المصدر مقطعين صريحين يفصل بينهما `/`. إذا تغيّر التركيب أو أصبح ملتبسًا يتوقف الإرسال للمراجعة. تطبيع النص هو Unicode NFC ومسافات متسقة، دون استبدال الحروف العربية المتمايزة.

**حدود متعمدة:** لا نستنتج المدينة من اسم الكلية، ولا نمط الدراسة من اسم البرنامج، ولا مواعيد أو حالة القبول. نستخدم الرابط الرسمي الموجود في الصف نفسه. تم فحص صفحة البرنامج `1894` ووجدت خطة مدمجة، لكن لم نتحقق من ربط خطط مستقلة بكل النسخ؛ لذلك يبقى `study_plan_url=null` لجميع السجلات. تبقى المدينة ونمط الدراسة والوصف غير المتوفر null. تظهر ملاحظات عمود السعر في `fee_observations_not_ingested` للمراجعة فقط؛ لا نرسلها كرسوم متحقق منها، ولا نستنتج أن كل البرامج مجانية. تبقى حقول الرسوم null و`tuition_verified=false`. لا تُجلب صفحات 333 برنامجًا إضافية، مما يقلل الطلبات والافتراضات.

## 1. الاستيراد إلى n8n

1. من n8n اختر استيراد سير عمل من ملف، وحدد `uqu-academic-programs.workflow.json`.
2. اتركه غير مفعّل. لا تضف مشغّلًا زمنيًا الآن.
3. راجع عقدة **Operator Configuration**: يجب أن تكون `mode: 'dry_run'`، وحقلا `liveConfirmation` و`approvedDatasetFingerprint` فارغين.
4. اترك عقدة **Campus Scoped Ingestion** معطلة كما وردت في الملف، ودون اعتماد في أول تجربة؛ المسار الافتراضي لا يصل إليها.
5. عقد Code تستخدم الوحدة المدمجة `crypto` لحساب SHA-256، ولا تستخدم مكتبات خارجية أو AI. في الاستضافة الذاتية التي تمنع الوحدات، اسمح بـ`crypto` فقط باستخدام `NODE_FUNCTION_ALLOW_BUILTIN=crypto` في بيئة تنفيذ Code/Task Runner بحسب إعداد n8n لديك. هذا إعداد n8n وليس إعداد Plesk أو Campus. لا تفتح قائمة السماح إلى `*`. توثيق n8n Cloud يذكر إتاحة `crypto` في Code.

الملف يستخدم Code v2 وHTTP Request v4.2 وIF v2.2 وWait v1.1. لا يحتاج إضافة مدفوعة. راجع [توثيق Code](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.code/) و[HTTP Request](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest/). نتائج الاختبار وحدود اختبار n8n الفعلي مسجلة في `VERIFICATION.md`؛ يجب فحص استيراده في إصدار المشغّل الذي ستستخدمه قبل أي تشغيل حي.

## 2. تجربة جافة بلا إرسال

شغّل **Manual Dry Run** من بداية سير العمل كاملًا. لا تنفذ عقدة Campus منفردة. المسار يمر بطلب HTML رسمي، ثم فحص الصفحة، ثم انتظار مهذب للصفحة التالية. عند النهاية تفحص عقدة **Final Report**:

- `status` يجب أن يكون `dry_run`، و`campus_requests=0`، و`errors=[]`.
- قارن `official_total_rows` و`fetched_rows`. افحص `pages`، و`parsed_programs`، و`duplicate_rows` و`batch_sizes`.
- راجع `sample` و`records`، خصوصًا الأسماء والدرجات والأقسام والساعات وروابط المصادر.
- احفظ `dataset_fingerprint` بعد مراجعة المجموعة. البصمة تشمل جميع الحقول المرسلة وترتيبًا ثابتًا بالمعرف؛ لا تتأثر بترتيب صفحات المصدر وحده.
- إذا كانت الحالة `blocked`، اقرأ `errors` ولا تتجاوز الحماية أو تقلل متطلبات التحقق. صفحة فارغة أو حظر أو تغيير HTML أو إجمالي متغير أو فقدان صف يمنع كل إرسال.

الحد الأعلى الافتراضي 10 صفحات من 100 صف؛ يمكن للمالك التقني رفعه بحد أقصى 50 صفحة بعد التحقق من نمو المصدر. لا تزيد سرعة الطلبات. لا يوجد حذف أو إخفاء أو مسح سجلات عند فقدان صفحة أو فشل مصدر أو تقلص مجموعة.

## 3. إعداد Campus بواسطة مدير المنصة

من المسار الخاص `/portal-control-x7k92` وبحساب Owner:

1. تأكد من تطبيق إصدار دليل البرامج الأكاديمية السابق وترحيله. لا يحتاج **هذا** التسليم أي ترحيل أو تعديل قاعدة بيانات أو إعداد Plesk.
2. افتح **مصادر الاستيراد** وأضف أو راجع مصدرًا مفعّلًا بالمفتاح `uqu-degrees`، مرتبطًا بجامعة أم القرى `uqu`، ورابطه `https://uqu.edu.sa/App/Degrees`. لا تغيّر مصدر الأخبار `uqu-rss`.
3. من **تكامل n8n وAPI** لجامعة أم القرى استخدم مفتاحًا جامعي النطاق موجودًا صالحًا، أو ولّد مفتاحًا وفق سياسة المنصة. لا تُلغِ مفاتيح سير الأخبار ولا تُدرها دون حاجة.
4. لا تستخدم جلسة المشرف أو المفتاح العالمي القديم؛ endpoint الأكاديمي يتطلب اعتماد الجامعة نفسها.

في n8n أنشئ اعتماد **Header Auth** باسم محلي واضح، ثم اختره في **Campus Scoped Ingestion**:

- Header Name: `Authorization`
- Header Value: `Bearer ` يتبعه مفتاح جامعة أم القرى الحقيقي داخل مخزن Credentials فقط.

لا تضع المفتاح في Code أو URL أو Set أو JSON أو ملف مستودع أو صورة شاشة. لا تصدّر الاعتمادات. قيد الوصول إلى n8n وبيانات تنفيذاته واضبط الاحتفاظ بها وفق حاجتك. عقدة HTTP تستخدم عنوان Campus ثابتًا ولا تتبع تحويلات، حتى لا يُعاد إرسال الاعتماد لمضيف آخر. [توثيق الاعتمادات](https://docs.n8n.io/integrations/builtin/credentials/httprequest/).

## 4. تمكين الاستيراد عمدًا

بعد مراجعة التجربة الجافة وتجهيز المصدر والاعتماد، غيّر الحقول التالية في **Operator Configuration**:

```js
mode: 'live',
liveConfirmation: 'SEND_REVIEWED_UQU_ACADEMIC_PROGRAMS',
approvedDatasetFingerprint: 'ضع هنا بصمة المجموعة التي راجعتها من Final Report'
```

فعّل عقدة **Campus Scoped Ingestion** بعد اختيار الاعتماد المحلي، ثم شغّل سير العمل كاملًا يدويًا. سيعيد جلب الدليل والتحقق منه قبل الإرسال. إذا تغيّر أي حقل في المجموعة عن التجربة المعتمدة، يتوقف عند `LIVE_APPROVAL_REQUIRED` بلا إرسال؛ أعده إلى dry run وراجع المجموعة الجديدة. هذه حماية مقصودة لأول استيراد. ضبط `mode` وحده لا يكفي. إعداد الاعتماد وحده لا يكفي. لا تنسخ البصمة من هذه الوثائق؛ استخدم تقرير تشغيلك الحالي.

كل طلب إلى `POST https://campus.estudy24.com/api/ingest/academic-programs` يحمل `{ "items": [...] }`، بحد أقصى 50 سجلًا وأقل من 1 MiB بالبايت الفعلي UTF-8. حقول snake_case مطابقة لـ[عقد Campus](../../../docs/ACADEMIC-PROGRAMS.md). لا يُرسل معرف الجامعة الداخلي؛ نطاق المفتاح هو السلطة، و`university_slug=uqu` فحص إضافي. يُحافظ على كل معرف رسمي عند إعادة المحاولة.

بعد التشغيل افحص `outcomes` و`attempts` و`counts`، ولا تعتبر `completed_with_errors` أو `blocked` نجاحًا كاملًا. `unconfirmed` يعني عدم وجود نتيجة مؤكدة لتلك السجلات، وليس أنها لم تصل قطعًا عند انقطاع اتصال. يمكن إعادة المحاولة بالمعرفات نفسها لأن Campus يدعم idempotency. لا تتبع التقرير برسالة نجاح عامة تخفي السجلات المرفوضة.

## التعامل مع النتائج والأخطاء

| الاستجابة | التصرف |
| --- | --- |
| 200 / 201 | تحقق من عدد النتائج والفهارس والنوع والعدادات، ثم سجّل كل نتيجة. |
| 207 | احتفظ بكل نتيجة؛ أعد فقط السجلات `failed` ذات `INGESTION_FAILED` مؤقتًا. لا تعاود السجلات الناجحة أو `rejected`. |
| 401 / 403 | أوقف الإرسال. صحح الاعتماد أو نطاق الجامعة أو ملكية المصدر. لا تعاود دون تصحيح. |
| 413 / 415 / 422 | أوقف الطلب ولا تعاوده دون تصحيح الحجم أو نوع المحتوى أو البيانات. لا تُقسّم طلبًا مرفوضًا عشوائيًا لإخفاء السبب. |
| 429 | احترم `Retry-After` مع backoff تصاعدي. تأخير أكبر من 300 ثانية يتطلب المشغّل بدل إعادة محاولة مبكرة. |
| 408 / 500 / 502 / 503 / 504 أو انقطاع الاتصال | إعادة محدودة بنفس الهويات، بتأخير تصاعدي؛ لا تفترض عدم حدوث كتابة إذا انقطع الاتصال. |
| تقرير ناقص/غير مطابق أو فهارس مكررة | أوقف العملية؛ لا تحسبه نجاحًا ولا تعدله تلقائيًا. |

بحد أقصى أربع محاولات افتراضيًا لكل صفحة/مجموعة سجلات متبقية، وفاصل لا يقل عن ثانيتين بين طلبات Campus، أي أقل من حد 60 طلبًا في الدقيقة. التأخير التصاعدي 2، 4، 8 ثوانٍ؛ قيمة `Retry-After` الأكبر محترمة ضمن الحد المذكور. لا تُعاد محاولة خطأ دائم تلقائيًا. تقرير كل محاولة يتضمن المعرفات والنتائج، دون المفتاح أو نص استثناءات HTTP الخام. يمكن لن8ن حفظ الاعتماد مشفرًا دون وجوده في التصدير.

## 5. المراجعة والنشر

افتح قسم **التخصصات والبرامج الأكاديمية** في إدارة Campus، ثم رشّح جامعة أم القرى. البرامج الجديدة تأتي `pending_review` حتى لو فُعّل النشر التلقائي لأخبار الجامعة. راجع المصدر والدرجة والكلية والساعات ثم انشر المسموح وفق الصلاحيات. وجود برنامج في الدليل لا يعني فتح القبول فيه. يحافظ Campus على التصحيحات اليدوية وحالة النشر/الإخفاء والحذف عند إعادة الاستيراد. سير العمل لا يطلب نشرًا أو حذفًا، ولا يتصرف في أخبار الجامعة.

بعد الانتهاء أعد `mode: 'dry_run'` وامسح التأكيد والبصمة وأعد تعطيل عقدة Campus لتقليل فرص تشغيل حي لاحق بالخطأ.

## 6. المزامنة الدورية لاحقًا

لا يوجد جدول مفعّل أو مُعد في هذا التسليم. بعد اعتماد تشغيل يدوي يمكن للمشغّل إضافة Schedule Trigger في n8n وربطه بمسار التهيئة نفسه، بدءًا بوضع dry run وبوتيرة منخفضة مثل أسبوعية. تظل بوابة البصمة تمنع إرسال مجموعة متغيرة دون مراجعة؛ ستحتاج الموافقة على بصمة جديدة أو سياسة تشغيل منفصلة يوافق عليها المالك مستقبلًا. لا تعطل تلك الحماية بصمت للحصول على تشغيل آلي. لا تضف أي مجدول داخل Next.js.

## الاختبارات المحلية وإعادة توليد التصدير

من جذر المستودع، دون اتصال بقاعدة بيانات أو Campus:

```sh
node --test integrations/n8n/uqu-academic/collector.test.cjs
node integrations/n8n/uqu-academic/build-workflow.cjs --check
```

اختبار مصدر رسمي اختياري للقراءة فقط، لا يملك منطق إرسال إلى Campus:

```sh
node integrations/n8n/uqu-academic/verify-live-source.cjs --fetch-official-source
```

يحفظ التقرير محليًا في `.npm-logs/uqu-academic-live-dry-run.json` المستبعد من Git. لا يُعاد تنزيل المصدر عند تشغيل اختبارات fixtures. خيار `--write-fixtures` منفصل وصريح لتحديث مقتطفات الاختبار عند الحاجة؛ راجع تغييراتها قبل اعتمادها. الملفات في `fixtures/` حقائق اختبار من المصدر الرسمي، وليست seed أو سجلات تُرسل إلى الإنتاج. لا يُحفظ HTML الصفحة الكامل بما يحتويه من مكونات تسجيل دخول أو رموز CSRF. شغّل `node integrations/n8n/uqu-academic/build-workflow.cjs` بعد تعديل المكتبة لإعادة توليد JSON؛ اختبار `--check` يكشف أي اختلاف.
